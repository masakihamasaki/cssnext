# コンテンツ展開パイプライン

最初に `.claude/work-style.md` を読む。何も公開・投稿しない。

## 考え方
- **元原稿は1つ。** 派生物は元原稿から機械的に作り、手で切り直さない。直すときは元原稿を直して作り直す。
- **版は1ファイルにまとめる。** 「最終」「確定」「v2」を別ファイルで増やさない。Docs は版の履歴で管理し、ファイル名は `<系列>_<番号3桁>_<題名>`。入稿用など形式が違うものだけ別ファイルにする。
- **作ったら記録する。** 何を作り、どこにあり、公開されたかを制作管理シートに残す（成果を後で追えるように）。

## 入力
- 元ネタ（Drive のファイル、URL、動画、貼り付けたテキスト）
- 作りたい形（指定がなければ下の表から元ネタに合うものを提案して確認する）

## 手順
1. **元原稿を作る**: 元ネタから、事実（出典つき）と考察を分けた元原稿を Docs で作る。媒体ごとの記事なら `article-pitch`、活動報告なら `activity-report` の手順を使う。
2. **派生物を作る**（必要なものだけ）:

| 形 | 作り方 | 保存 |
|---|---|---|
| 媒体記事 | 元原稿を媒体の型（リード→本文→示唆→出典）に整える | Docs / Word |
| note | 一人称・読み物調に書き換え、見出しを3〜5個 | Docs |
| ナレーション動画 | `narration-slides`（変換ツールを使う） | pptx → Drive |
| SNS投稿 | X 用140字以内×3案、LinkedIn / Facebook 用300字×1案。数字は元原稿と同じ表記 | 報告の中だけ |
| 動画の概要欄 | 要約3行＋出典＋関連記事URL（公開後に入れる欄は空ける） | 報告の中だけ |
| 書籍の章 | 執筆仕様に合わせて章構成にし、`manuscript-check` で点検 | Docs |

3. **数字・固有名詞をそろえる**: 派生物どうしで数字・肩書・社名の表記が違っていないかを確認し、違いがあれば元原稿に合わせる。
4. **制作管理シートの行を用意**: Drive で制作管理・台帳のスプレッドシートを探し、その列名に合わせて「元原稿／派生物／保存先／状態（台本完成・動画化済み・公開済み）／公開URL」を1行ずつ作る。**書き込みは本人が頼んだときだけ**。それ以外は表として報告する。
5. **止まっている案件を拾う**: 管理シートに「台本完成」などのまま7日以上動いていない行があれば、次に何をすれば進むかを一覧にする。

## 出力
作ったファイルのリンク、SNS案と概要欄、数字・表記の食い違い、管理シートに入れる行、止まっている案件。
